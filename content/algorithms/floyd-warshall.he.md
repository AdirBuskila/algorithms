**המטרה:** מסלול קצר ביותר בין **כל זוגות** הקודקודים (all-pairs shortest paths) — לא רק ממקור יחיד.

- ✅ **מטפל במשקלים שליליים.**
- ❌ **אינו מטפל במעגלים שליליים.**
- **תכנון דינמי** על קודקוד ביניים `k`.

> [!note] היכן הוא ממוקם בין השלושה
> | אלגוריתם | מוצא | משקלים שליליים |
> |---|---|---|
> | [[Dijkstra's Algorithm\|דייקסטרה]] | קודקוד אחד → כל הקודקודים | ❌ |
> | [[Bellman-Ford Algorithm\|בלמן-פורד]] | קודקוד אחד → כל הקודקודים | ✅ |
> | **פלויד–וורשל** | **כל הזוגות** | ✅ |

## איך זה עובד

נשמור מטריצה `dist` בגודל `V × V`, כאשר `dist[i][j]` הוא המרחק הטוב ביותר הידוע מ-`i` ל-`j`. אז, קודקוד ביניים `k` אחד בכל פעם, נשאל: *האם קצר יותר ללכת מ-`i` ל-`j` דרך `k`?*

$$\text{dist}[i][j] = \min\big(\text{dist}[i][j],\ \text{dist}[i][k] + \text{dist}[k][j]\big)$$

לאחר שאיפשרנו לכל קודקוד `1…V` לשמש כביניים, `dist` מכילה את כל המרחקים הקצרים ביותר.

## פסאודו-קוד

```text
let V = number of vertices in graph
let dist = V × V array of minimum distances initialized to ∞

for each vertex v
    dist[v][v] ← 0                 // a node reaches itself at cost 0
for each edge (u, v)
    dist[u][v] ← weight(u, v)      // fill in the direct edges

for k from 1 to V                  // intermediate vertex
    for i from 1 to V              // source
        for j from 1 to V          // destination
            if dist[i][j] > dist[i][k] + dist[k][j]
                dist[i][j] ← dist[i][k] + dist[k][j]
            end if
```

המטריצה נקראת כ**שורות = קודקוד "מ-"**, **עמודות = קודקוד "אל"**, כך ש-`dist[i][j]` נמצא בשורה `i`, עמודה `j`.

## דוגמה

קשתות הגרף: `2→1 (4)`, `1→3 (−2)`, `2→3 (3)`, `3→4 (2)`, `4→2 (−1)`. שים `0` על האלכסון, הכנס כל משקל קשת לתא שלו, והשאר את השאר `∞`:

| מ- \ אל | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| **1** | 0 | ∞ | −2 | ∞ |
| **2** | 4 | 0 | 3 | ∞ |
| **3** | ∞ | ∞ | 0 | 2 |
| **4** | ∞ | −1 | ∞ | 0 |

סרוק `k = 1 → 4`; כל מעבר קורא את שורה `k` ועמודה `k` ומשפר כל תא שאפשר. כמה עדכונים (השאר נובעים מאותו תנאי `if dist[i][j] > dist[i][k] + dist[k][j]`):

- **`k = 1`:** `dist[2][3]` → `4 + (−2)` = **2** (מנצח את 3).
- **`k = 2`:** `dist[4][1]` → `−1 + 4` = **3** (היה ∞); `dist[4][3]` → `−1 + 2` = **1**.
- **`k = 3`:** `dist[1][4]` → `−2 + 2` = **0**; `dist[2][4]` → `2 + 2` = **4**.
- **`k = 4`:** `dist[1][2]` → `0 + (−1)` = **−1**; `dist[3][2]` → `2 + (−1)` = **1**.

**המטריצה הסופית** (מרחקים קצרים ביותר בין כל הזוגות):

| מ- \ אל | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| **1** | 0 | −1 | −2 | 0 |
| **2** | 4 | 0 | 2 | 4 |
| **3** | 5 | 1 | 0 | 2 |
| **4** | 3 | −1 | 1 | 0 |

> [!tip] זיהוי מעגל שלילי
> לאחר שהאלגוריתם מסתיים, אם תא אלכסוני כלשהו `dist[v][v] < 0`, אז `v` נמצא על מעגל שלילי — מסלול שיוצא מ-`v` וחוזר אליו כשהוא *מאבד* משקל כולל.

## איך זה מופיע במבחן

פלויד–וורשל הוא **הקבוע של הרב-ברירה** — כמעט בכל מבחן 2024–2025 יש סעיף **3ד** שקורא או משחזר מטריצת פלויד–וורשל (תת-נושא **6ג**). כל שאלות 6ג:

- **משמעות `D⁽ᵏ⁾[i][j]`.** *(2024 קיץ מועד א, שאלה 3ד)* — למה שווה `D⁽²⁾[1][4]`? *רמז:* המסלול הקל `1→4` שעובר **רק דרך `1, 2`** כקודקודי ביניים. המעריך `k` = "מותר להשתמש בביניים מתוך `{1..k}`" עונה על אלו מיד.
- **שחזור מסלול ממטריצת האבות `P`.** *(2024 סמ"ב מבחן לדוגמה, שאלה 3ד)* — שחזר מסלול קצר מ-`P`; *רמז:* עקוב אחר `P[i][j]` לאחור מ-`j` ל-`i`. *(2024 סמ"ב מועד ב / מועד מיוחד, שאלה 3ד; 2024 קיץ מועד ב / ג, שאלה 3ד)* — שחזר/פרש את המטריצה (מסלול קצר בין שני צמתים). *(2025 קיץ מועד ב, שאלה 3ד)* — שחזר מסלול `1→6` ממטריצת predecessors בת 7 צמתים.
- **האם `k` נחת על מסלול קצר?** *(2025 קיץ מועד א, שאלה 1ג)* — הוכח/הפרך: אם באיטרציה `k` בוצע `D[i][j] = D[i][k] + D[k][j]`, אז `k` על מסלול קצר ביותר `i→j` ב-`G`.

> [!tip] הוא מחשב גם סגור טרנזיטיבי
> החלף `min / +` ב-`OR / AND` בוליאניים, ופלויד–וורשל הופך ל**נגישות** בסיבוכיות `O(|V|^3)` — ה[[Transitive Closure|סגור הטרנזיטיבי]] הבוליאני `G*`, שאלת תכנון חוזרת בנושא 5.
