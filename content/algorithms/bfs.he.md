**המטרה:** ממקור `s`, לחשב את **מרחק השכבה** `d[v] = δ(s,v)` — מספר ה**קשתות** המינימלי על מסלול `s→v` כלשהו בגרף **לא-ממושקל** — ולבנות את עץ ה-BFS באמצעות `π`.

- מבקר בקודקודים בסדר מרחק עולה, ולכן התור תמיד **מסודר ברמות**: הערכים בו נבדלים בלכל היותר 1.
- למסלולים קצרים בגרף ממושקל השתמש ב-[[Dijkstra's Algorithm|דייקסטרה]] במקום; BFS הוא המקרה הפרטי הלא-ממושקל (כל קשת במשקל 1).
- השווה ל-[[Depth-First Search (DFS)|סריקת DFS]]: BFS משתמש ב**תור** וסורק לפי מרחק, ואילו DFS משתמש ברקורסיה וסורק לפי עומק.

## איך זה עובד

1. צבע כל קודקוד ב**לבן**, אתחל `d[v] = ∞` ו-`π[v] = NIL`.
2. קבע `d[s] = 0`, צבע את `s` ב**אפור**, והכנס את `s` לתור.
3. כל עוד התור אינו ריק, הוצא `u`. לכל שכן `v` ב-`Adj[u]` שעדיין לבן: צבע אותו אפור, קבע `d[v] = d[u] + 1`, קבע `π[v] = u`, והכנס את `v` לתור.
4. צבע את `u` ב**שחור** לאחר שכל שכניו עובדו. בפעם הראשונה ש-`u` נכנס לתור, `d[u]` כבר שווה ל-`δ(s,u)`.

## פסאודו-קוד

```text
BFS(G, s):
    for each v in V:
        d[v] <- ∞;  π[v] <- NIL;  color[v] <- WHITE
    d[s] <- 0;  color[s] <- GRAY
    Q <- {s}
    while Q ≠ ∅:
        u <- DEQUEUE(Q)
        for each v in Adj[u]:
            if color[v] = WHITE:
                color[v] <- GRAY
                d[v] <- d[u] + 1
                π[v] <- u
                ENQUEUE(Q, v)
        color[u] <- BLACK
```

## שימושים

- **קשתות על מסלול קצר.** קשת `(u,v)` נמצאת על מסלול קצר ביותר **כלשהו** מ-`s` **⇔** `d[v] = d[u] + 1`. כל קשת שנכשלת בבדיקה זו היא "מיותרת" (לא על אף מסלול קצר).
- **ספירת מסלולים קצרים.** החזק מערך נוסף `p[v]` עם `p[s] = 1`. כשמגיעים לשכן בשכבה הבאה `v` מתוך `u` (כלומר `d[v] = d[u] + 1`), צבור `p[v] += p[u]`. בסיום `p[v]` הוא מספר המסלולים הקצרים `s→v`.
- **קוטר ומרכז של עץ (2-BFS).** בצע BFS מקודקוד כלשהו כדי למצוא את הקודקוד הרחוק ביותר `u`; בצע BFS שוב מ-`u` כדי למצוא את הקודקוד הרחוק ביותר `v`. המסלול `u…v` הוא **קוטר**, `dist(u,v)` הוא אורכו, ו**אמצעו** הוא מרכז.

## דוגמה

גרף לא-ממושקל, מקור = **A**, שכבות לפי מרחק:

| שכבה `d` | קודקודים | הערות |
|---|---|---|
| 0 | A | המקור |
| 1 | B, C | שכנים ישירים של A |
| 2 | D, E | מגיעים מ-B או מ-C |
| 3 | F | מגיע מ-D |

אם גם B וגם C מחוברים ל-D, אז `p[D] = p[B] + p[C] = 1 + 1 = 2`: קיימים **שני** מסלולים קצרים מ-A ל-D.

> [!note] מדוע התור נשאר מסודר ברמות
> קודקוד נכנס לתור בדיוק כשהוא מתגלה לראשונה, ולכן מרחקו נקבע באותו רגע. מכיוון שאנו תמיד מוציאים קודם את הקודקוד הוותיק ביותר (בעל המרחק הקטן ביותר), המרחקים בתור לעולם אינם נבדלים ביותר מ-1.

## איך זה מופיע במבחן

BFS מופיע כסעיף השלמת-קוד בפסאודו-קוד, כשאלת "תכנן אלגוריתם לינארי" על עצים, ובטענות הוכח/הפרך על עץ ה-BFS.

- **ספירת מסלולים / קשתות על מסלול קצר.** *(2022 סמ"ב מועד ב, שאלה 4א-ב)* — השלם את `BFS_update(G,s)` כך שיחשב גם את `d[v]` וגם את מספר המסלולים הקצרים `p[v]`; *רמז:* על שכן בשכבה הבאה, `p[v] += p[u]`. *(2023 סמ"ב מועד ב, שאלה 4א-ב)* — צייר את עץ ה-BFS ומצא את כל הקשתות ה"מיותרות" (לינארי: BFS, ואז השאר רק את `d[v] = d[u] + 1`).
- **קוטר ומרכז של עץ.** *(2025 סמ"ב מועד ב, שאלה 2)* — אלגוריתם לינארי ל**מרכז** של עץ (קודקוד הממזער את המרחק המקסימלי); *רמז:* מצא את הקוטר בשני BFS, החזר את אמצעו. *(2ב — ייתכנו שני מרכזים כשהקוטר אי-זוגי.)* *(2023 סמ"ב מועד ב, שאלה 1 — לא נכון)* — קיצור הדרך לקוטר "מחק קשת `(a,b)`, BFS מכל אחד, החזר `da+db+1`" **שגוי** לעץ; מצא דוגמה נגדית.
- **המעגל הקצר ביותר דרך `s`.** *(2023 סמ"ב מועד מיוחד, שאלה 2א-ב)* — האם `BFS_update` המחזיר את אורך המעגל הקצר ביותר דרך `s` עובד בגרף **מכוון**? ובלא-מכוון? *רמז:* ההבדל הוא הקשת החוזרת לאב.
- **מבנה עץ ה-BFS (הוכח/הפרך ורב-ברירה).** *(2024 סמ"ב מועד ב, שאלה 1א)* — אם כל מקור `s` נותן אותו `π` מ-`BFS(G,s)`, האם מספר רכיבי הקשירות בהכרח שווה ל-`|V|`? *(2025 סמ"ב מועד ב, שאלה 3ג — רב-ברירה)* — הוספת זמני גילוי/סיום ל-BFS: `b(π(v)) < b(v) < f(π(v)) < f(v)` (אין קינון מלא כמו ב-[[Depth-First Search (DFS)|סריקת DFS]]).

> [!tip] קוטר של עץ = שני BFS
> בצע BFS מקודקוד כלשהו אל הקודקוד הרחוק ביותר `u`; בצע BFS מ-`u` אל הקודקוד הרחוק ביותר `v`. אז `dist(u,v)` הוא ה**קוטר**, וה**מרכז** הוא אמצע המסלול `u…v`. תבנית 2-BFS זו היא המענה כמעט לכל שאלת מרחקים על עץ.
